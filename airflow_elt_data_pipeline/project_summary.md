# ELT Data Pipeline (Airflow + Snowflake) Project Summary

## AWS IAM
- Create an IAM role needed to transfer data from an S3 bucket to the Snowflake bronze layer using an Airflow DAG.
- Since this role will be used by Snowflake to access an S3 bucket from this account, the role must be created for this AWS account and must require an external ID that will be generated by Snowflake.
- Add the following permissions to the role:
    - AmazonS3FullAccess

## AWS S3
- Create a General Purpose S3 bucket to store airflow DAG and requirement files.
    - Enable bucket versioning for this bucket.
- Create a General Purpose S3 bucket to store the raw data loaded from the HTTP endpoint by the Python script. This bucket will be used to transfer the raw data to Snowflake for transformation.
    - Keep all default settings for this bucket.
- Create a 'dags' folder in the airflow file bucket. Also, upload the `requirements.txt` file to the root directory of this bucket.

## AWS Managed Apache Airflow
- Create an environment:
    - Provide a meaningful name
    - Select the second most recent version of Airflow.
    - Choose the previously created airflow file S3 bucket.
    - Select the `dags/` folder within the S3 bucket.
    - Select the `requirments.txt` file within the S3 bucket for the optional requirements file.
    - Create an MWAA VPC, leaving all settings as default. Once the stack is created, select the VPC that was created as part of the stack. Ensure the two default subnets are automatically populated.
    - Choose 'Public network' for 'Web server access'.
    - Ensure 'Create new security group' is enabled.
    - Select the 'mw1.micro' environment class.
    - Create a new execution role for the workflow, providing a meaningful name. Once the environment is created, attach the following policies to the role:
        - AmazonS3FullAccess
    - Verify settings and create environment.


## Snowflake
- Create a database to store the the data retrieved from the HTTP endpoint by Airflow.
- Create separate schemas for the bronze, silver, and gold layers of the medallion architecture.
- Create a storage integration between Snowflake and S3, providing the ARN of the previously created IAM role and the URI of the previously created data bucket.
    - Use the `STORAGE_AWS_IAM_USER_ARN` and `STORAGE_AWS_EXTERNAL_ID` properties of the storage integration to update the trust policy of the IAM role.
- Create a stage to store the Airflow data from S3, specifying the previously created storage integration and URI of the previously created airflow data S3 bucket.
- Bronze Layer:
    - Create tables for the raw data from S3.
- Silver Layer:
    - Create a stored procedure that normalizes raw patient data.
    - Create a stored procedure that normalizes raw treatment data.
    - Create a stored procedure that normalizes raw visit data.
    - The above stored procedures will be executed by the Airflow directed acyclic graph (DAG) and create the necessary tables.
- Gold Layer:
    - Create a stored procedure that aggregates patient visit data (total patients and hospitals visited) by city.
    - Create a stored procedure that aggregates hospital performance data (total visits, total treatments, average treatment cost, and treatment success rate).
    - Create a stored procedure that aggregates patient visit data (total visits and average days between visits) by patient.
    - Create a stored procedure that aggregates patient treatment data (total visits, total treatments, total spent, and average cost per treatment) by patient.
    - The above stored procedures will be executed by the Airflow DAG and create the necessary tables.

## Airflow
- Access the airflow UI through the AWS MWAA Console.
- Under Admin > Connections, create a new connection:
    - Provide a meaningful connection ID.
    -  Select Snowflake for the connection type.
    - Provide the previously created Bronze schema as the default schema.
    - Provide Snowflake login credentials.
    - Provide the Snowflake account identifier.
    - Provide the Snowflake `COMPUTE_WH` as the warehouse (the same warehouse where the airflow DB was created).
    - Provide the previously created Snowflake airflow DB.
    - Provide the Snowflake `ACCOUNTADMIN` role (the same role used to create the airflow DB).
    - Save the connection.
- Create a `test_snowflake_airflow_connection.py` file to test the connection between Airflow and Snowflake. Once created, upload the file to the `dags` folder of the airflow file S3 bucket.
    - Uploading the `test_snowflake_airflow_connection.py` file to the airflow file S3 bucket will make the DAG available in the Airflow UI. Once the DAG is available, execute it in the Airflow UI.
    - After executing the DAG in the Airflow UI, ensure the connection was successful by looking for the `SELECT CURRENT_TIMESTAMP;` query from the `test_snowflake_airflow_connection.py` file. This query should be located in the query history in the Snowflake UI.
- Create a `healthcare_elt_pipeline.py` file, which will act as the DAG that retrieves the data from the HTTP endpoint, uploads it to the airflow data S3 bucket, and loads it into the Snowflake bronze layer. The script then executes the stored procedures in the bronze, silver, and gold layers.
    - After creating the `healthcare_elt_pipeline.py` file, upload the file to the `dags` folder of the airflow file S3 bucket. This will make the DAG available in the Airflow UI. Once the DAG is available, you can view it in the airflow UI to ensure it is correct.
    - After verifying the DAG is correct, execute it in the Airflow UI. Once the DAG is finished executing, verify the respective tables were created and populated in the bronze, silver, and gold schemas in Snowflake. This can be done with a simple `SELECT *` statement in Snowflake.
